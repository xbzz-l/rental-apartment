## Docker 一键部署编排（新增）

为服务器部署补齐容器化方案，新增 6 个文件，未改动任何业务代码：

| 文件 | 作用 |
| --- | --- |
| `docker-compose.yml` | 五个服务：mysql / server / app / admin / bi |
| `.env.example` | 端口、数据库密码、管理员密码、项目名等可调项 |
| `docker/server.Dockerfile` | 多阶段：maven 构建 → temurin 17 JRE alpine 运行 |
| `docker/web.Dockerfile` | 三端共用，`ARG APP_DIR` 区分；node 构建 → nginx 托管 |
| `docker/nginx/default.conf` | SPA fallback + `/api`、`/images` 反代 + 静态缓存策略 |
| `.dockerignore` | 排除 node_modules / dist / target / 文档，构建上下文瘦身 |

**关键设计**

- **只暴露三个前端端口**（默认 8081/8082/8083），后端 8080 与 MySQL 3306 均不映射到宿主机，全部走容器内网。
- **必须覆盖 `server.address`**：`application.yml` 里是 `127.0.0.1`（本地开发锁回环），容器内改为 `SERVER_ADDRESS=0.0.0.0`，否则同网络下的 nginx 连不上。
- 数据源、JWT 密钥、管理员账号全部用环境变量注入（`SPRING_DATASOURCE_*`、`JWT_SECRET`、`APP_ADMIN_*`），镜像里不留密码。
- 时区三处对齐：容器 `TZ=Asia/Shanghai`、JDBC `serverTimezone=Asia/Shanghai`、MySQL `--default-time-zone=+08:00`。BI 的月份统计依赖 `create_time`，时区不一致会导致跨月错位。
- MySQL 用具名卷 `${COMPOSE_PROJECT_NAME}-mysql-data`；`down` 不丢数据，`down -v` 才删。
- 多套部署靠 `.env` 的 `COMPOSE_PROJECT_NAME` + 三个端口；多机共库靠 `DB_HOST` / `DB_PORT`。
- Maven 依赖用 BuildKit cache mount（`--mount=type=cache,target=/root/.m2/repository`），项目自带 `.mvn/settings.xml` 的阿里云镜像被复制进构建镜像。

- 三端 `npm run build` 实测全部成功（app 3.4s / admin 15.2s / bi 31s），产物 dist 结构与 nginx root 一致，验证完已删除 dist。
